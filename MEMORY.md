## Workflow

[LEARN:workflow] Spec-then-plan catches ambiguity before planning — reduces rework 30-50%. Use for complex/ambiguous tasks.

[LEARN:workflow] Plans, specs, and session logs must live on disk (not just in conversation) to survive compression.

[LEARN:workflow] Context survival: MEMORY.md + session log + plan must be on disk before compression.

## Documentation

[LEARN:documentation] Update README when adding features. Stale docs break trust.

[LEARN:documentation] Keep templates generic — examples from multiple domains, not prescriptive rules.

## Design

[LEARN:design] Framework-oriented > prescriptive. Provide templates users customize, not rigid rules.

## Skills

[LEARN:skills] Effective skill descriptions use trigger phrases users actually say. Skills need 3 sections: instructions, examples, troubleshooting.

## Memory

[LEARN:memory] Two-tier memory: MEMORY.md (generic, committed) + personal-memory.md (machine-specific, gitignored). See meta-governance.md.
